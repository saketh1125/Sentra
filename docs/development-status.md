**Cross-file limitation experiment: INCONCLUSIVE — do not assert either way.**
The experiment planted a single-file SQL-injection fixture (CASE A) and a cross-file
equivalent (CASE B). Neither was flagged, because the tested rulesets do not include a SQL
injection rule. The recorded conclusion in the evidence file is
`intra_procedural_limitation_demonstrated: false`, with the note *"Investigate before relying
on the claim; do not assert the limitation either way."*
Semgrep vendor documentation and the research document both state the single-function limit;
**our experiment did not confirm it empirically.** The honest position is: limitation is
documented by the vendor and consistent with every observation, but not yet demonstrated by
us. A separate observation *was* confirmed: pattern rules that match a dangerous API call
itself (e.g. `subprocess` with `shell=True`) fire wherever the sink sits, including
cross-file, because no taint flow is required to match the pattern.

## 7. Known Problems

### 7.1 OOM incident — the session-termination cause (see `docs/resource-incident.md`)

Established from `dmesg`/systemd journal:

```
Out of memory: Killed process 63235 (python) total-vm:76059836kB, anon-rss:51940076kB
ptyxis-spawn-...scope: Killing process 72099 (opencode) with signal SIGKILL
Failed with result 'oom-kill'
The kernel OOM killer killed some processes in this unit.
```

A `python` process reached **≈51.9 GB RSS** on a 62 GiB machine and was OOM-killed; the kernel
then OOM-killed the `opencode` session itself. The python process was the S4 retrieval spike.
**The precise in-process cause is not established** — unbounded `passage_embed` batching and
accumulated ONNX model sessions are prime suspects but unproven.

**Status: Unknown / needs verification.** Do not rerun S4 as previously written.

### 7.2 Chunker defects found and fixed (regression-guarded)

1. **Duplicate chunks.** A `decorated_definition` wrapper and its inner `function_definition`
   were both emitted at identical byte ranges — e.g. `HTTPBasicAuth.__init__` twice at
   `bytes[2755,2830]`. Removing these removed **786 phantom chunks** repo-wide
   (8,356 → 7,570). These would have corrupted retrieval and double-counted findings.
2. **Self-nested qualified names**, e.g. `to_key_val_list.to_key_val_list`, which poison
   qualified-name lookups downstream.

Both are fixed and the spike now **asserts** 0 duplicates and 0 self-nested names so they
cannot silently return.

### 7.3 Harness bugs found (measurement integrity)

1. **`extra.lines` is not the source snippet.** Semgrep's `extra.lines` is the *rendered
   message* (observed value: `"requires login"`). Verifying against it scored 0/13. The
   verifier now uses byte `start.offset`, which is authoritative — 13/13 correct.
2. **`.gitignore` hazard, both tools.** Semgrep scanned **zero files** and exited 0, looking
   like a clean repository; osv-scanner exited 128 with `No package sources found`. Cause:
   both honour `.gitignore`, and Sentra's own `.gitignore` excludes `data/repos/*`. This
   produced a **false 0/21 recall** in the first S2b run. Fixed with `--no-git-ignore` /
   `--no-ignore`, plus a hard guard that refuses to report a zero-scan result as a measurement.
3. **Verification cost misattributed.** Rebuilding the line-offset table per chunk made parsing
   look 7× slower than it is. Fixed; the guard now asserts non-zero scanned-file counts.

### 7.4 sentence-transformers abandoned

`uv pip install sentence-transformers` pulled **>8 GB of NVIDIA CUDA wheels**
(`nvidia-cusolver`, `nvidia-nccl`, `nvidia-cufft`, `triton`) for a CPU-only project. Even with
the PyTorch CPU index, uv merged indexes and still resolved CUDA dependencies. Switched to
**fastembed + onnxruntime**, which needs no torch. The uv cache was cleared.

### 7.5 Detection recall below the O3 target

Semgrep CE recall on our ground-truth corpus is **61.9%**, not the PRC's ≥80% for O3. This is
a property of the tool, predicted by the research document. **Needs your ruling** — see
`DECISION_LOG.md` §D9 and §"Open items". Recommendation: report O3 per layer rather than
quietly redefining the seeded set to flatter the tool.

## 8. Current Development Position

**Resume at spike S4, re-engineered to be memory-bounded.** Everything before it is complete
and verified. S1–S3 results are final and committed; do not rerun them.

Concretely, S4 needs these changes before it is run again:

1. **Free each model explicitly** (`del model; gc.collect()`) and run **one candidate per
   process** rather than all five in one process.
2. **Bound the embedding input**: batch the corpus in fixed slices (e.g. 64 chunks) and
   cap total chunks embedded per run.
3. **Drop `.tolist()`** on embedding matrices — it materialises Python floats and multiplies
   memory. Score with numpy directly and keep a single normalised matrix.
4. **Cap threads** (`OMP_NUM_THREADS=4`, `ONNXRUNTIME` thread limits) to avoid ONNX spawning
   many arenas.
5. **Run under an explicit address-space limit** (e.g. `ulimit -v`) so a regression fails fast
   instead of OOM-killing the session.
6. **Reuse cached models** where already downloaded; do not re-download.
